# createLogger

Create a namespaced logger. The returned `Logger` emits through the globally configured handler and respects the configured level and namespace filter.

## Signature

```ts
function createLogger(namespace: string): Logger
```

## Parameters

| Name | Type | Default | Description |
|---|---|---|---|
| `namespace` | `string` | — | Logger namespace. Shown in the default output and matched against `configure({ namespaces })`. |

## Returns

`Logger` — object with `error`, `warn`, `info`, `debug` methods:

```ts
interface Logger {
  error(message: string, data?: unknown): void;
  warn(message: string, data?: unknown): void;
  info(message: string, data?: unknown): void;
  debug(message: string, data?: unknown): void;
}
```

## Example

```ts
import { createLogger } from "@parity/product-sdk";

const log = createLogger("my-app:checkout");

log.info("Cart submitted", { cartId: "abc", total: 4200 });
log.error("Payment failed", { code: 402 });
```

## Notes

- Loggers are cheap to create — construct one per module rather than passing them around.
- Level and handler live in shared module state. Changing them via [`configure`](/api/sdk/configure) affects every existing `Logger`.
- Calls below the configured level are skipped before the handler runs; formatting the `data` payload has no cost when suppressed.
